## 1. Problem / goal
A wall is a `surface_area` takeoff = traced plan LF × height → flat SF
(`shapeMetrics.js:20-30`); the tile engine is `floor_area`-only (`tileTakeoff.js:311`).
Goal (design §3.5): unwrap a straight wall run into an L×H **elevation rectangle**, tile
it with the shipped floor engine → real piece/cut/corner counts, cut sheet, grout,
purchase-unit order — plus a flattened elevation preview. **M10 does NOT change net
wall SF** (still LF×height); it changes what you get from it. Membrane SF = M11.

## 2. The reuse verdict (validated by review)
`solveTileLayout`, `classifyLayout`, `countsBySku`, `optimizeOrigin`/`effectiveTileSetup`
are **pure over `ring_ft` + `tile_setup`** (`tileSolve.ts:39`, `classify.ts:353`,
`tiles.ts:52`, `optimize.ts` — reviewer-confirmed: a rectangle ring gives ≤9 origin
evals, no pathology on a thin strip). `summarizeShape` reads ONLY
`tile_setup/ring_ft/holes_ft/tile_layout` — never `verts_norm/measure_role/dims/upp/
computed` (`tileTakeoff.js:133-230`). Multi-SKU painting and origin-honoring reuse on a
strip verbatim. **The core is free; the boundary is the work.**

## 3. Trigger + a ruling
**Ruling (auto-trigger):** a `surface_area` shape auto-tiles iff its condition has a
`tile_setup` — same as a `floor_area` shape. Rationale: consistent with floors, and
`tile_setup` isn't arbitrarily addable to a condition today (it comes only from the
seed/duplicate), so the "silently re-price an existing wall condition" risk the review
flagged is low. *Cost if wrong:* a user who duplicated a tiled condition and added wall
traces sees tile counts appear on those walls; recoverable, and surfaced (§5 preview +
report). If this proves surprising, a per-condition "tile walls" opt-in is the follow-up
— NOT "tile only when no floor shapes" (that flips silently when a floor is added).

## 4. Data model
No new shape fields. Reuse: `surface_area` shape's geometry (recompute L, §5.1), its
resolved height (§5.1), optional `shape.tile_layout` (origin/rotation override — but see
§5.6: wall strips ignore `edge_overrides`). `holes_ft = []` (openings are M11).

## 5. Engine — the full gate list

### 5.1 Strip ring + resolved height (new, pure)
`web/src/lib/tileWall/strip.ts`:
```ts
export function wallStripRing(length_ft: number, height_ft: number): [number, number][] {
  return [[0, 0], [length_ft, 0], [length_ft, height_ft], [0, height_ft]]; // elevation frame, feet
}
```
- **L = `openLen(verts) * upp`, recomputed** in the gate (NOT `computed.perimeter_lf`,
  which is `toFixed(2)`-rounded, `shapeMetrics.js:29` — floors use exact `verts*dims*upp`;
  match that exactness and avoid a freshness dependency on `computed`).
- **H = resolved height** via the SHARED precedence helper (per-shape `height_override`
  → shape `height_ft` → condition `height_ft`). **Extract the existing rule into one
  helper** (it's duplicated at `shapeMetrics.js:25`, `measurementBreakdown.js:9`,
  `TakeoffCanvas.jsx:4105`); do not add a 4th copy.
- Degenerate (L≤0 or H≤0) ⇒ skip tiling AND record it as an excluded-with-reason (a
  counter + QA note, §5.5), not a silent drop.

### 5.3 Panel elevation preview (the "panel" surface of §F:111)
Render the selected wall's strip as a flattened L×H elevation, quads at their SKU
colors, reusing `tileOverlayPrimitives(summary.layout, previewUpp, skuColor)` — pure
`px = ft/upp`, no `toPage`, no plan coupling (`tileOverlay.ts:56-70`, reviewer-confirmed);
`previewUpp` = fit-L×H-into-the-preview-box. Two wiring gaps to close (both real):
- **Thread `byShape` into `TilePanel`** — today only `byCond` (`layouts`) reaches it
  (`TakeoffCanvas.jsx:10250-10266`); the preview needs the per-shape strip summary.
- **Extend the selection gate** `TakeoffCanvas.jsx:10229` (`selShape.measure_role ===
  "floor_area"`) to admit `surface_area`, so a selected wall reaches the panel (and its
  `tile_layout` origin override becomes reachable).
- **Per-selected-wall** preview (a condition can hold N walls; `byShape` is one summary
  per shape id): preview the *selected* surface shape's strip. No per-condition strip
  list at M10.
- Update the empty-state copy (`TilePanel.jsx:465`, currently "its floor areas get
  figured into tiles") for a wall-only condition.

### 5.4 M10 figures FIELD only — skip edges/trim/joints for strips
`summarizeShape` also runs `edgeExposures`/`trimTallies`/`movementJoints` on the ring
(`:210-228`). For a wall these are floor/edge concepts (base/cove trim, EJ171 field
joints) — M11 territory. By default trim is empty (confirmed-only, no `edge_overrides`),
but **`movementJoints` runs on any ring** → a bare wall would report spurious joint LF.
So the surface path skips edge/trim/joint *derivation* (field tile + cut sheet + grout +
order only) via a `skipEdges` branch in `summarizeShape`. **Pinned: `skipEdges`
ZERO-FILLS `summary.trim` (empty `byKind`) and `summary.joints` (zeros) — it must NOT
omit them.** The `byCond` rollup reads both UNCONDITIONALLY (`tileTakeoff.js:370`
`summary.trim.byKind.length`; `:391-395` `agg.jointTotals.* += summary.joints.*`), so an
omit variant TypeErrors on the first wall shape; the report seam is already guarded
(`:617-620`), so the rollup is the sole exposure. Zero-fill keeps §5.2's "rollup: no
change" literally true, and also neutralizes the stale-`edge_overrides` risk (a
`tile_layout` carrying floor edge indices that don't map to the synthetic 4-edge
rectangle).

### 5.5 QA extends to strips (the "figured ⇒ audited" invariant)
`tileQA.ts:87` and the canvas feeder `TakeoffCanvas.jsx:1357` are `floor_area`-only, so
walls would be figured but never audited (`tileQA.ts:6-8` invariant). Extend `tileWarnings`
to surface-strip shapes: sliver cuts on the strip, a zero-/degenerate-height wall (§5.1),
an unscaled-sheet wall, and the multi-segment warning (§5.6). This is what makes
"cut-accurate" honest for walls.

### 5.6 Multi-segment runs — restrict + warn
A `surface_area` trace can be a bent polyline; `openLen` sums the whole run, so
`wallStripRing(total, H)` unwraps it as ONE seamless strip — which **understates cut
count** (two 5ft walls need two edge-cut pairs; one 10ft strip has one) and the preview
shows no corner. Per-segment splitting breaks the `byShape` one-summary-per-id contract,
so M10 = **whole-run-as-strip + a QA warning** when a tiled surface has > 2 vertices
("Wall tiled as one L×H strip; corners not modeled — split the run for per-segment
cuts"). Not left as an open question.

## 6. Non-goals (M11+)
Openings/niches (holes), niche interior faces, multi-course base, stacked bands, the
wet-area membrane engine; **Marked-Set / DXF elevation placement** (now *delivered* as a
deferral via the §5.2 outbound guards, not merely asserted); on-canvas in-plan wall
rendering; multi-sheet/match-line; per-segment corner modeling.

## 7. Acceptance criteria (TDD)
Engine (`web/test/`):
- `wallStripRing(10,8)` = `[[0,0],[10,0],[10,8],[0,8]]`.
- A **2-vertex** straight `surface_area` (openLen→10ft, resolved H=8) on a grid 12×12
  `tile_setup` → `byShape` has a strip layout with correct full/cut/corner for 10×8
  (NOT a "degenerate ring" exclusion — guards the `:314` fix).
- Height precedence resolves H (override > shape > condition); **editing the height
  changes the cached strip** (add/flip a height input, assert the layout re-solves —
  guards the cache-sig fix; a naive test without the cache would miss it, so exercise
  the cache path).
- **Role-retag cache:** re-tag a ≥3-vertex shape `floor_area`→`surface_area` with
  verts/tile_setup/tile_layout unchanged ⇒ the cached summary re-solves to a strip
  (NOT a stale floor-frame hit) — guards the `measure_role`-in-sig fix.
- Multi-SKU on a wall: a painted 2×2 checkerboard → strip `countsBySku` splits; `by_sku`.
- Strip figures NO trim/movement-joint LF (§5.4): assert `trim_lf`/`joint_lf` === **0**
  (zero-filled, not absent) for a wall row even with a `tile_layout`, and that the
  `byCond` rollup does not throw on a wall shape.
- Multi-segment (>2 verts) tiled surface → a QA warning is emitted (§5.6).
- **Back-compat:** floor-only project ⇒ `computeTileTakeoff` byte-identical; a
  `surface_area` whose condition has NO `tile_setup` ⇒ still excluded (unchanged
  `wall_sf`); **the marked-set tile page excludes wall shapes** (guard §5.2). Use a
  **≥3-vertex** `surface_area` wall for this assertion — a 2-vertex wall is already
  blocked by the pre-existing `markedset.js:1006` `ring.length<3` skip, so it would pass
  vacuously without the `:998` fix. Assert both: no wall quads drawn (`:998` guard) AND
  a wall-only tiled condition produces NO tile page (`:925` floor-only predicate).
- QA: an unscaled-sheet or sliver-edge wall raises a warning (§5.5).

Browser (controller-verified, screenshot): draw a wall (Surface Area) under a
`tile_setup` condition with a height → select it → the panel shows a flattened tiled
elevation preview + the wall's counts/cut-sheet/order; paint a 2-color unit → the
preview + counts go multi-color; edit the height → the preview re-solves; the Marked-Set
PDF shows NO wall tile page.
