## M11a — Openings

### Model

On the `surface_area` shape (alongside `face_side`, `endpoint_exposed`, `wall_corner_overrides` — `tileSetup.ts:50-54`):

```ts
type WallOpening = {
  id: string;                         // stable, minted (not positional) — survives vertex edits
  kind: "door" | "window" | "niche";
  seg: number;                        // index of the RAW verts_norm segment the opening sits on
  offset_ft: number;                  // from that segment's start vertex, along the segment
  sill_ft: number;                    // bottom above floor datum (door = 0)
  w_ft: number; h_ft: number;
  depth_ft?: number;                  // tiled return depth (window/door jambs+head+sill; niche depth). 0/absent = no returns
  edge?: "cased" | "finished";        // opening edge: cased = tile dies into casing/frame (no trim); finished = trim at the arris
  sill_finish?: "tile" | "stone";     // window/niche sill: tile, or a separate stone/solid-surface piece (EA)
  prefab?: boolean;                   // niche: a prefab insert (e.g. KERDI-BOARD-SN), counted EA
  deduct?: boolean;                   // D2 — default true
  label?: string;
};
wall_openings?: WallOpening[];
```

Defaults by kind: door → `edge:"cased"`, `depth_ft:0`, `sill_ft:0`. Window → `edge:"finished"` if `depth_ft>0`, else `"cased"`; `sill_finish:"tile"`. Niche → `edge:"finished"`, `depth_ft:0.29` (3.5 in stud cavity), `prefab:false`.

Per-run layout field: `wall_center_on?: string` (an opening `id`) — D4.

**Why `seg` + `offset`, not absolute `u`:** `u = cumLen(raw segs before seg) + offset`, so moving a far vertex doesn't slide the opening; and the collinear collapse in `unwrapRun` (`unwrap.ts:35-73`) doesn't change cumulative length, so raw-segment keying survives it. Stable `id` (not array index) avoids the positional-key fragility the spec accepted for `wall_corner_overrides` (§8).

**v1 constraints (rejected with a warning, not silently clamped):** an opening must sit inside one segment (can't straddle a fold); inside `0 ≤ sill < sill+h ≤ H`; openings on one run may not overlap. A door with `sill_ft>0` is allowed (a raised threshold) but warns.

**Penetrations (pipes, valves, outlets) are NOT openings** — the VA spec says fit tile around them so escutcheons cover the cut [STD]; no deduction. They move to M11c as an EA list for seals.

### Global constraints

- **Reconciliation, updated (replaces spec §3.4 "hole-free only"):**
  (a) **Extent identity (exact):** `tiled_extent_sf == L×H − Σ deducted opening areas + Σ return/niche face areas`. Purely geometric, no engine output.
  (b) **Coverage (grout-bounded):** engine `keptArea_sf` within the existing tolerance of `tiled_extent_sf × tileArea/moduleArea`. Never assert `keptArea == extent`.
  (c) **Back-compat:** `wall_sf` from `totals.js:49` is unchanged by openings (D1).
- **The engine already handles holes.** `solveTileLayout` takes `holes_ft` (`tileSolve.ts:39-44,160`); `classifyLayout` emits `cls:"hole"` for tiles wholly inside (`classify.ts:386-389`) and `cut` for partial; `countsBySku` never purchases `hole` cells (`tiles.ts:4-7,34`). M11a passes holes through; it does not touch the classifier.
- **Opening trim comes from the opening list, never from the hole rings.** Same rule as Slice A corners: `edgeExposures` walks the outer ring only (`tileEdges/expose.ts:38-93`) — don't teach it holes. Opening trim is new run-keyed `trim.byKind` entries built in `tileWall/`.
- **Floors, non-tile walls, and hole-free walls are byte-for-byte unchanged.** A wall with no `wall_openings` must produce identical summaries (regression test in Task 3).
- **Test convention:** `node:test` + `node:assert/strict`, flat `web/test/tileWall*.test.ts`, `.ts` imports; fixtures `dims={w:100,h:100}`, `upp=0.1`, `make12x12Setup()` (`tileWallSummarize.test.ts:14-25`); takeoff helpers from `tileWallTakeoff.test.ts:25-90`.

### Task 4: Opening-edge trim

Per opening with `edge:"finished"`, per research Q3 (VA: bullnose at external corners and edges, square edges not acceptable [STD]; metal profiles by LF [MFR]):

| `wall_edge_finish` | Opening perimeter (jambs + head; + sill edge for window/niche) |
|---|---|
| `profile` | profile LF = exposed perimeter; + 4 EA corner connectors per rectangular opening (`wall_opening_corner`) |
| `bullnose` | bullnose EA per course (jambs) + per column (head/sill); converts the slot's field cut, same no-double-count rule as spec §5 |

## M11b — Base, cap, bands (outline)

- **Base course:** condition-level `wall_base?: { sku_id, kind: "cove"|"bullnose"|"flat", h_in }`. The field starts above the base: V datum moves from 0 to `h_in` (spec §4.4 datum, shifted). Base LF = run L − Σ door widths (doors from M11a). Inside/outside base corner pieces EA from the run's fold classification (VA spec defines cove-base corner shapes [STD]; Daltile sells L/R cove corners [MFR]).
- **Wainscot cap:** `wall_cap?: { sku_id | profile, kind: "bullnose"|"pencil"|"chair_rail"|"profile" }` on the top edge when the tile stops below the ceiling (`top_exposed: boolean` per run). LF = run L − openings crossing the top; outside-corner caps EA. VA: flat cap where the wainscot is flush with the wall above [STD].
- **Horizontal bands:** `wall_bands?: [{ v_ft, h_in, sku_id }]` — V-ranges that split the strip into stacked sub-strips sharing the run's U origin (not the floor M7 concentric inset — codemap §4). Reuse M7's per-SKU band aggregation.
- Reconciliation: base + field + bands + cap cover `extent_sf` exactly (extent identity per stack).

## M11c — Wet area (outline)

- `wet?: { height_ft, membrane_unit: "sf"|"roll", roll_w_ft? }` per wall run (or per condition). Distinct from `height_ft` (design §3.6).
- **Membrane SF** = wet-zone strip area − deducted openings in the wet zone + returns and niche interiors in the wet zone. Seams: LF from roll width (or 2 in overlap rule). **Inside/outside corner preforms EA** from fold classification (Schluter KERDI-KERECK at all corners [MFR]). Niche: interior membrane or prefab.
- **Penetrations:** `wall_penetrations?: [{ id, kind: "pipe"|"valve", seg, offset_ft, v_ft }]` → seal EA (KERDI-SEAL-PS / -MV [MFR]); no tile deduction (VA [STD]).
- **Wet height default:** to the shower head at minimum (Schluter [MFR]; TCNA B422 "to the shower head", via TCNA quote [EDU]). IRC R307.2's 6 ft is a finish-height rule, not membrane — label it so. The "72 in above drain" claim is unverified [AGG] — don't use it.
- **Slope flags:** QA flag for a niche shelf or in-shower window sill without slope (TCNA via CTEF: horizontal surfaces slope to drain [EDU]; trade pitch figures conflict — flag, don't prescribe).
- Pan, curb and drain stay in M12/M13.
